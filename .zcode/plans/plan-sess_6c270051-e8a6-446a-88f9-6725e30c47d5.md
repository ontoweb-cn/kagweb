| 项 | 决定 |

| P0 授权粒度 | **只加 `agent_loop_cli` 一个字段**，专管"能否在本机 spawn agent 进程"。HTTP 族保持默认放行（它不 spawn 本地进程，无此风险） |

## P0 — CLI/ACP 族需管理员显式授权（安全，必须先做）

**设计**：新增授权维度 `agent_loop_cli`，语义"允许该用户在本服务器上运行 agent 进程"。
- `None`（默认）→ **拒绝**（fail-closed；现有部署无此字段，升级后自动收紧）
- `True` → 允许
- `False` → 拒绝（与 `None` 等效，供 UI 显式表达）

HTTP 族继续走既有的 `agent_loop` 维度（默认允许，改动前已如此，非本次引入）。

### 后端

1. **`kagweb/services/session/turns/request_preparer.py`** — `_effective_required_service` 按 family 分派：
   ```python
   profile = resolve_primary_profile(settings)
   if profile is None:
       return "llm"
   return "agent_loop_cli" if preset_family(profile["preset"]) == "cli" else "agent_loop"
   ```
   配套：`preset_family` 来自 `agent_loop.builtin`（已存在）；复用 P2 传入的 block。

2. **`kagweb/multi_user/grants.py`** — `empty_grant` 加 `"agent_loop_cli": None`（含三态注释）；`normalize_grant` 加 `bool(...) if isinstance(..., bool) else None`。`learner_grant` **不设**该键（默认拒绝已是正确的最保守态）。

3. **`kagweb/multi_user/model_access.py`** — `redacted_model_access` 增合成条目：
   ```python

       {"source": "deployment", "available": grant.get("agent_loop_cli") is True}

   ```
   与既有 `agent_loop`（`is not False`）方向相反——这正是本项的意义。仍是 server-only（HTTP 面只暴露 `allowed_llm_options`，只读 `llm` 键）。

### 前端（授权需要 UI 才能操作，属 P0）

   - 文案需点明后果，例如：`Run agent processes on this host` / `Unchecked by default. This backend runs as the server user, so enabling it grants the user code execution on this machine.`

7. **`tests/multi_user/`** — `agent_loop_cli` 三态往返 + `redacted_model_access` 两个维度的默认值方向相反。

## P1 — URL 编码与日志脱敏

### P1-1 URL 路径注入（混淆代理）

`kagweb/services/agent_loop/http_backend.py`：
- 新增 `_path_segment(value: str) -> str` = `quote(str(value), safe="")`（`urllib.parse.quote`）。
- `_runs_url(*suffix)` 对每个 suffix 编码 → 修掉既有 `_run_id` 同类问题。
- `respond_clarify`（`:682`）的 `self._session_id` 编码。

理由（实测）：`..` 会被 httpx 规范化，可把带 `Authorization: Bearer <api_key>` 的请求打到配置主机上的**任意路径**——混淆代理。`?`/`#` 可注入 query/fragment。`//evil` 不改 host（已实测），但路径穿越与凭据误投是真实的。

### P1-2 日志脱敏

同文件 `:620-626`：`logger.debug` 改为**只记录 `type`/`event` 名**，不记录事件体，并对二者做长度截断（`%.100s`）。当前 `%.200s` 打印整个 `obj`，而事件体恰含 `output`（完整模型回答）/`result`（工具结果）/`arguments`。

实测缓解事实：默认日志级别 `WARNING`，`kagweb.jsonl` 内 0 条 DEBUG —— 当前不生效，但开 DEBUG 即成内容落盘通道，且 `%r` 打印的 `type`/`event` 完全无长度限制（远端可控）。

**测试**：新增一条单测，断言未识别事件经 `caplog` 记录后**不含** `output` 文本；并对 `..`/`?` 的 session_id 断言生成的 URL 路径被编码。

## P2 — 重复读设置、孤儿模块

### P2-1 消除重复读（改注释 + 局部复用）

- `_effective_required_service(capability, block=None)` 接受已读 block；preparer 在门禁处读一次并复用（P0 已含此形态）。
- **修正 `kagweb/capabilities/chat/capability.py:118` 的注释**——它现在声称 "One settings read per turn"，但 preparer 与 capability 各读一次是结构性的（它们分属不同类、不同阶段）。改为准确描述：capability 每回合读一次；门禁另读一次用于鉴权判定。

实测依据：稳态下 `_load_or_create` 的 `normalized == loaded`，**不写盘**；只是多一次 1.8KB 文件读。故不引入全局缓存（收益小、失效风险大）。

### P2-2 删除孤儿模块

`git rm kagweb/api/routers/tools.py`（已确认全仓零引用：我删了挂载与导入，文件本身遗留）。确认 `get_enabled_optional_tools` 仍被 `partners.py:688` 与 `partners/runtime.py:719` 使用——那是 service 层导出，不受影响。

**验证**：`pytest tests/ -q`（预期 2218+ 通过，仍只有已知 10 个 partner 环境失败）。

## 风险与已知边界

| 风险 | 说明 |
|---|---|
| **P0 是有意的权限收紧** | 升级后，非管理员在 CLI/ACP 族 primary 下**立刻失去**聊天能力，直到管理员在授权里勾选。这是期望行为（把"以服务器 uid 执行代码"的授权交回管理员），但需在 commit message 与代码注释里写明，避免被当成回归。 |
| HTTP 族不受影响 | 它不 spawn 本地进程；`agent_loop` 维度保持默认放行，多用户部署的可用性（批次 2 的目标）不变。 |
| ACP 与 one-shot CLI 同族 | `intellect` 是 `family="cli"` + `transport="acp"`，`preset_family` 返回 `"cli"`，自然落进 CLI 分支——无需特判。 |
| 前端控件文案硬编码英文 | 与 `CheckRow` 既有用法一致；不新增 i18n 词条（避免破坏 en/zh locale parity）。 |
| 未覆盖的残留风险 | CLI 子进程仍以服务器 uid 运行、无沙箱——这是**架构既定**（文档多处声明为 single-operator shape）。本计划只把授权收敛到管理员，不引入沙箱。若未来需要真正的多用户隔离，属独立议题。 |
